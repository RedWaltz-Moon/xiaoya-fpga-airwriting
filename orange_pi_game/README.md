# 小芽 · 空中书写乐园

面向数字与英文逐字符练习的空中书写应用，词库包含基础生活词及四六级词表中的常用词，支持 Windows 和香橙派 Linux。FPGA 采集笔尖或指尖轨迹，主机完成字符识别、课程交互、学习记录和小票生成。

## 功能

- **三种课程**：数字练习、单词练习、数字＋单词混写挑战；完成基础课程后解锁混写。
- **循序渐进**：6089 个英文单词，结合近期避重复、按词长进阶与跨启动错题复习。
- **自主表达**：自由拼词与电子黑板，支持大小写、数字、空格和换行。
- **持续积累**：保存练习数、星星、通关与错题记录，重启后继续学习。
- **双语学习小票**：按单次练习选择、预览和打印，小票语言跟随中英文界面，使用 RD-E10 内置 GBK/ASCII 字库。
- **轻量部署**：62 类轨迹识别使用 NumPy CPU 推理，不依赖 YOLO、PyTorch 或 NPU。

> 本目录为主机应用，运行需要配套 FPGA 终端。主机显示交互界面，FPGA HDMI 独立显示摄像头和轨迹，不向主机传输实时视频。打印功能需要支持扩展协议的 FPGA 固件。

## 快速开始

准备[部署文件](#runtime-layout)和[运行环境](#installation)，连接 FPGA 串口。在香橙派本地图形桌面终端中，进入 `orange_pi_game/` 运行：

```bash
python3 start.py --windowed
```

Windows 使用安装了依赖的 Python 环境，在相同目录执行：

```cmd
python start.py --windowed
```

启动后选择串口编号或输入完整设备名。也可直接指定端口；以下设备名需替换为实际连接：

```bash
python3 start.py /dev/ttyUSB0 --windowed
```

```cmd
python start.py COM3 --windowed
```

从项目根目录启动时使用 `python3 orange_pi_game/start.py --windowed`（Windows 使用 `python`）。模型、推理脚本、学习档案和日志均相对于项目根目录定位。

日常选课、答题和返回均可通过确认后的书写字符操作。部分 Linux 桌面全屏兼容性不同，默认建议使用窗口模式；省略 `--windowed` 可全屏运行。`start.py` 不接受回放参数。

## 运行环境

| 平台 | 参考运行环境 |
| --- | --- |
| 香橙派AI Pro | Ubuntu 22.04.3 LTS、Python 3.9.2、NumPy 1.26.4、pygame 2、pyserial；本地图形桌面窗口运行 |
| Windows | Python 3.12.9、pygame 2.6.1、NumPy、pyserial |

使用CPU推理，不要求香橙派NPU。其他板卡/系统需自行验证图形、串口与性能。

在用于运行应用的 Python 环境中检查依赖和串口：

```bash
python3 -c "import sys, pygame, numpy, serial; print(sys.executable); print('依赖检查通过')"
python3 -m serial.tools.list_ports
```

Windows 使用 `python`。如需安装依赖，在相同环境执行：

```bash
python3 -m pip install pygame numpy pyserial
```

中文字体读取系统已有Noto CJK/文泉驿或Windows微软雅黑。没有中文字体时界面回退英文；不随项目打包字体。Linux可用`fc-list :lang=zh family file`检查。

串口为**115200、8N1、无流控**。需要设备读写权限，且不能同时被采集器、串口助手或独立推理服务占用。TTL接线需TX/RX交叉、共地、匹配3.3V电平；不要随意连接USB转串口供电脚。

## 操作说明

每个输入字符，包括菜单数字，都按**写好 → 确认 → 等待结果 → 清空 → 写下一个**操作。

| FPGA输入 | 书写 | 确认发送 | 清空当前笔迹 |
| --- | --- | --- | --- |
| PEN | 红笔头 | S4或红外4 | S3或红外3 |
| HAND | 佩戴绿手套，伸出单食指 | 比耶 | 五指张开 |

S1/红外1切换模式并清空板端当前笔迹/字符，主机无需换模型或重启。HAND的S3/S4是颜色阈值调节，不是确认/清空。游戏内导航不依赖键盘鼠标；首次选择串口及退出程序仍需终端或系统操作。

### 首页

写对应数字并确认：

| 数字 | 页面 |
| --- | --- |
| 1 | 数字练习 |
| 2 | 单词练习 |
| 3 | 数字＋单词混写挑战 |
| 4 | 自由拼词 / 小黑板 |
| 5 | 学习档案 |
| 6 | 切换中文 / English |

数字与单词各完整通关至少一次后解锁混写，解锁可跨启动保存。

### 中英文切换

在**首页写 `6` 并确认**即可切换界面语言，也可点击右下角语言按钮；无串口的键盘演示可按 `6`。切换仅在首页生效，课程和黑板中的数字 `6` 不受影响。

中文界面生成中文标题/字段的小票，英文界面生成英文小票；题目、原学习日期、成绩和黑板正文不翻译、不改写。同一条历史记录可以分别以两种语言打印。小票在打开预览时冻结；更换语言后需重新打开预览。

语言选择仅对本次启动生效：启动时找到系统中文字体则默认中文，否则使用英文并提示缺少字体。不修改学习档案，也不改变 62 类识别模型或大小写匹配规则。

### 课程与返回

- 数字每组10题，0～9各一次，顺序随机；气球落地后等待输入，不因写得慢扣分。
- 单词每组三词，整组合计不超过20个字母；词库6089词：1055个3～4字母词、5034个5～10字母词。题目首字母大写、其余小写，例如`Cat`、`Apple`、`Technology`；超过10字母的词不进入题库。
- 出题兼顾覆盖、近期避重复及错题复习。单词课与混写各自通关两组后，在第3/6/9…组最后一词加入长词；长度上限依次为6、8、10，之后保持10，其余两词保持3～4字母。这里按词长控制书写量，不以词长代替正式词汇难度评级。
- 混写每组三个数字和三个完整单词交替，数字与字母合计最多20个；出题时为数字预留三个位置，再选择完整单词，不截断单词。错误保留当前位置供重试。
- 首次进入每门课程显示4秒引导；同一次启动再次进入不重复引导。
- 当前目标不是`0`时，8秒内**两次独立写0并确认**返回首页；目标为0时先完成该题。提交其他字符会取消第一次返回提示。
- 通关后写`1`再玩一组、`2`回首页、`3`打印学习小票；打印前还需写`1`确认或`2`取消。暂停/离开确认页写`1`继续、`2`回首页。
- 仅`C/c、S/s、O/o、Z/z`四组在题目匹配时忽略大小写，其他字母严格区分，数字0不等于O/o。回传、日志及黑板保留原预测，不按题目篡改识别结果。

### 词库来源与维护

词库由308个生活词和公开四六级词条合并组成。四六级词条来自 [KyleBing/english-vocabulary](https://github.com/KyleBing/english-vocabulary) 的CET-4、CET-6顺序词表，固定提交为 [`c4c6c80879ff17d7025c28fb853a4991c8e6be6a`](https://github.com/KyleBing/english-vocabulary/tree/c4c6c80879ff17d7025c28fb853a4991c8e6be6a)。两表13159条原始记录经3～10个纯字母、中文释义和去重处理后，得到6000个词条，合并后共6089个不同单词；重复词采用生活词表的释义。释义保留中文主释义并去除附带音标，题库不含短语、缩写或连字符词。

词库用于出题，不限制识别模型的单词范围，也不是官方考试大纲或词频排名。模型仍逐字符识别原有62类，无需增加模型类别或修改FPGA协议。

- `vocabulary.py`维护原生活词与合并规则，原释义优先；短词池、长词池和档案长度上限自动派生。
- `vocabulary_cet.py`保存整理后的外部词表、来源指纹及完整BSD-3-Clause声明，运行时不联网。
- 部署需同时包含两个词表模块及配套的`app.py`、`core.py`和`learning.py`。升级可沿用现有学习档案，无需清空记录。
- 学习小票包含较长的练习和复习词时，若超出512字节，仅把装饰分隔线由32列缩短为12列；日期、成绩和正文保留，打印协议不变。

### 自由拼词 / 小黑板

逐字符追加原识别值，支持英文大小写、数字、空格和换行，最多120字符。显示末四行，全文自动保存；右侧最近轨迹是已确认的一笔，不是实时视频。

写`0`打开工具，再写操作数字：

| 数字 | 动作 |
| --- | --- |
| 1 | 删除最后一个字符 |
| 2 | 插入空格 |
| 3 | 换行 |
| 4 | 清空黑板：再写1确认或2取消 |
| 5 | 回首页 |
| 6 | 插入数字0 |
| 7 | 打印黑板内容：再写1确认或2取消 |
| 0 | 关闭工具，不编辑 |

实际输入0使用“0打开工具 → 6插入0”。板端清空笔迹**不会删除主机黑板或学习档案**。

### 学习档案

默认显示**汇总**：累计作答、星星、总体正确率、学习分钟、练习次数、三课程通关/未完成情况、最长连对与待复习内容。汇总随有效答题增量保存，页面直接读取，不逐帧扫描全部历史。

页面写`1`练数字、`2`练单词、`3`进入“练习记录”、`0`回首页。左侧选中记录，右侧显示该次成绩；页面不会自行选课或打印。

有效课程答案无论正确或错误都计入练习数；正确字符奖励一颗星，完整课组才增加通关数。菜单、重复/迟到事件、自由拼词不计成绩。后续课组穿插错题；同组错过的内容保留，另一组干净完成后才从复习集合移除。

#### 单次记录与选择打印

每组课程生成独立编号，有效作答后开始留档；通关、离开、重开或正常退出时结束记录。未作答的空课程不保存。记录包含：

- 课程类别、完整题目、开始/结束日期时间及原时区。
- 完成状态、有效练习用时、得分/目标数、正确率、作答/重试次数、首次答对数及最长连对。
- 每次有效作答的目标字符、实际收到的识别字符、当时判定、位置和相对用时；详情/小票提供错字与待复习摘要。

汇总和单次记录分别保存于同一个`learning.json`的汇总字段与`sessions`列表中，不是按分钟或日期合并记录。默认看汇总，需要核对某次内容或打印时再打开历史。历史按新到旧排列，支持跨启动保留：

```text
首页5 → 学习档案3 → 历史页1～4选中一条 → 5打印 → 1确认 / 2取消
                         7上一页 / 8下一页       0返回汇总
```

每张小票仅包含选中的一次练习。查看、取消和打印不重复计分；补打保留原学习日期。也可在通关页面使用 `3 → 1` 打印刚完成的记录。

日期读取主机本地时钟并保存时区偏移，不依赖联网校时。有效用时不含引导和暂停；异常退出的记录标记为“意外中断”，结束时间取最后保存时间。停留在通关页面不延长已结束记录的用时。

档案格式为 `version=2`。程序不自动清空或迁移旧文件：`version=1`、未知版本和损坏文件均保留原件并停止写入，界面提示“存档不可用”。需要新建档案时，退出程序后备份或移除 `user_data/learning.json`；合法 v2 档案可跨启动保留。

档案版本与 UART 协议版本相互独立；串口帧仍使用 V1。

成绩以游戏当时收到的识别字符及判定为准，不是对原始笔迹的独立人工评分。一次答对指该字符位置没有重试便通过；正确率为正确字符数÷有效作答数，未完成记录另显示实际进度。

<a id="architecture"></a>

## 系统架构

```text
摄像头 → FPGA检测/轨迹 → UART确认后的64点 → 主机CPU识别 → 游戏页面
                   ↑                         │
                   └── UART单字符结果回传 ────┘
```

- **FPGA HDMI**：实时摄像头、检测调试、轨迹、字符回显和开机健康信息；合法回传后播放柔和电子“喵”。
- **主机显示**：数字、单词、混写、自由拼词和学习档案；不接收实时视频。
- **识别**：现用NumPy轨迹最近模板模型，支持`0–9 / A–Z / a–z`共62类，不需要YOLO、PyTorch或NPU运行时。
- **PEN/HAND**：共用同一模型和V1协议，游戏不区分模式；视觉和模式选择由FPGA负责。
- FPGA只显示一个结果字符。完整单词、成绩和存档由主机管理，逐字符立即判定，逐字符交互，不依赖整词结束计时。

学习档案和日志在首次使用时写入 `user_data/learning.json` 和 `logs/game/`，不属于部署所需文件。个人数据不应包含在公开仓库中。

更新应用前先退出程序，再覆盖运行文件；未更换的模型和推理脚本可保留。不要覆盖个人 `user_data/`。FPGA 工程、开发缓存和串口日志无需上传到主机运行目录。

## 显示与高级设置

默认1920×1080画布原生绘制；窗口初始1280×720，可拉大，缩放保持比例。全屏沿用桌面尺寸，不改变系统HDMI模式。性能不足时，在**项目根目录**使用高级入口：

```bash
python3 -m orange_pi_game.app --port /dev/ttyUSB0 --model models/pen_tr01_to_val01_62_baseline.npz --bd-shape --render-height 720 --windowed
```

其他选项包括`--font 字体路径`、`--profile 档案路径`、`--log-dir 日志目录`、`--display 显示器编号`。用`python3 -m orange_pi_game.app --help`查看。

直接模块入口必须同时指定`--port`与`--model`；保持短入口识别行为时不要漏掉`--bd-shape`。

## 学习记录与日志

默认数据路径相对于项目根目录，即 `orange_pi_game/start.py` 的上一级目录：

| 路径 | 用途 | 删除影响 |
| --- | --- | --- |
| `user_data/learning.json` | 汇总、逐次学习明细、通关/解锁、错题和黑板 | 全部重置，混写重新锁定 |

**先退出游戏并备份记录**，否则内存记录可能重新写回。Linux在项目根目录按需执行：

```bash
# 重置学习记录和黑板，不删除模型。
rm -f -- user_data/learning.json

# 仅清串口日志；目录不存在时无需执行。
find ./logs/game -maxdepth 1 -type f -name 'trajectory_*.jsonl' -delete
```

公开日志前检查轨迹、端口、用户名/路径及模型来源信息；运行日志不是人工标注训练集。

<a id="protocol"></a>

## 接口与识别限制

V1上行每帧138字节，含64个归一化(x,y)点；下行11字节，含同一8位seq和单个ASCII字符。CRC16多项式`0x1021`、初值`0xFFFF`，覆盖版本至载荷，低字节先发。实现见[独立推理脚本](../tools/trajectory_infer/pen_uart_reply.py)。

后台断线每2秒重试；重连丢弃旧串口缓冲，须清空重写。同一连接0.75秒内连续完全相同的帧可重回结果，但不重复导航/计分。seq会回绕或复位归零，不是永久唯一事件号；V1无模式、ACK、复位通知，快速复位后完全相同笔迹存在理论歧义。

显示的处理时间不含摄像头、书写及UART上行等待，不是端到端延迟；学习档案也不是识别准确率报告。HAND与PEN可混用模型，但书写风格不同可能导致识别效果不同。

<a id="print-link"></a>

## E10 学习小票

打印由主机生成小票文本，经原通信链路提交给 FPGA，再由独立 UART 发往打印机。打印仅在确认后提交，不会在答题或通关时自动触发；打印状态不参与课程判题。

### 打印操作

- **黑板内容**：首页写`4` → 写好内容 → `0`打开工具 → `7`打印内容 → `1`确认发送或`2`取消。
- **学习小票**：任一课程通关 → `3`打印学习小票 → `1`确认发送或`2`取消。
- **历史单次小票**：首页`5`学习档案 → `3`练习记录 → `1～4`选中一条 → `5`打印 → `1`确认或`2`取消；`7/8`翻页，`0`返回汇总。
- 每个导航数字都须按原规则清空板端笔迹、重新书写并确认；打印弹窗中的输入不会追加到黑板或计入课程答题数。
- 打印前显示纸面预览，长黑板可用`7/8`翻页；预览与发送取自同一份冻结内容，发送行序按下述 E10 出纸方向补偿。查看、翻页、返回不发送数据，只有`1`确认才提交一次。发送不会清空原内容；发送后`0/2`返回不取消已接受的任务。

### 纸面排版

每行最多 **32 个西文列，或 16 个汉字**；中文占两列，混排按实际列宽换行，不拆开汉字。预览保留最终纸面的正常阅读顺序。对于新行出现在上一行上方的 E10 出纸方向，游戏在发送出口将**排版后的行倒序发送**，不倒转行内字符或 GBK 字节；末尾走纸保留三个空行。黑板保留大小写、空格与空行，日期为生成时间；学习小票使用所选练习的原日期。中文界面示例：

```text
          小芽学习记录
--------------------------------
编号：000001 | 数字练习
开始：2026-10-15 19:09:39+08:00
结束：2026-10-15 19:10:21+08:00
已完成
--------------------------------
完成：10/10  正确率：83.3%
作答：12次  重试：2次
首答正确：9  最长连对：8
有效练习：0分37秒
--------------------------------
练习：2 5 3 1 7 8 0 4 6 9
待复习：3
易混淆：3>1(1次); 3>j(1次)
--------------------------------
```

切换英文界面后，同一记录使用 `LEARNING RECORD`、`Start / End`、`Score / Accuracy`、`Practice / Review / Mixups` 等英文字段。两种语言都通过 GBK 链路发送，英文 ASCII 字节保持不变；不需要给打印机发送额外的语言切换指令。

行序补偿只作用于游戏打印，不修改学习档案、预览、FPGA或串口协议。观察 CH340 原始数据时，末尾内容会先到、标题最后到，这是该补偿的预期行为；独立 `print_link.py --text` 排错工具仍原样发送，不替代游戏的纸面排版。其他出纸方向或修改过正反向设置的设备需重新核对，不能假定所有 E10 固件方向相同。

每任务不超过 **512 个 GBK 编码字节**，不是 512 个字符；中文通常占两字节，换行和标题同样计入。错字摘要最多列出 4 类组合，更多时标注剩余类别数；完整答题明细保留在档案中。输出固定 GBK 与 CRLF，不支持 UTF-8、表情、图片、自动裁纸或字体控制命令；不支持的字符明确报错，不静默替换或丢字。

字号沿用打印机设置：西文 12×24、汉字 24×24、横向 1 倍时，32 西文列 / 16 汉字对应 48 mm。其他字库或放大设置的实际占宽不同。游戏仍识别原有 62 类英数字符；中文仅用于小票标题和字段，不表示新增中文手写识别。

### E10 接线与配置

打印接口面向**北京荣达制造的 RD-E10 TTL 低压供电型号**。硬件依据为[官方规格](https://www.rd-cn.com/index-product-detail-id-110.html)和《RD-E10系列用户开发手册_20231027》（内部标题 RD-E1 系列，V1.0）：纸宽 57±0.5 mm、有效打印宽度 48 mm / 384 点、接收缓存 2 KiB。低压型号手册供电范围为 5～8.5 V。本项目由**开发板的5V电源接口**为打印机供电，并与FPGA共地；GPIO0_3仅传输串口数据。

| 链路 | 波特率 | 格式 |
| --- | --- | --- |
| 香橙派 ↔ FPGA主机口 | 115200 | 8N1 |
| FPGA GPIO0_3/A16 → E10 RXD | **9600** | 8N1，打印专用 |

先断电接线，核实是**TTL而非RS232/485版本**，确认RX允许3.3V输入；电平不匹配时使用合适的单向转换，不能直接把5V输出送入FPGA。GPIO0 BANK保持3.3V。

| FPGA / 电源端 | E10端 | 说明 |
| --- | --- | --- |
| GPIO0_3 / A16 | RXD | 仅向打印机发送文本 |
| 开发板 GND | GND / 电源负极 | 与FPGA共地 |
| 开发板5V电源接口 | 电源正极 | 按实物供电插座标识接线 |
| 不接FPGA | TXD、CTS/BUSY | 未使用；不得将5V信号直接接入FPGA |

自检确认`9600,N,8,1`后，**不按任何键断电重启一次**再打印；手册说明自检后会进入DUMP模式，停在其中会将正文打成十六进制。绿灯在线常亮、装纸正确后，先打印一份短黑板文本。

短文本传输利用打印机的 2 KiB 接收缓存，单票不超过 512 字节。由于未接入 BUSY 和缺纸反馈，仅支持**单张低频打印**；应等待实际出纸完成后再提交下一张，不适合无人值守批量打印。

### 固件兼容与串口排错

配套的`acg720_dvp_ov5640_hdmi/`工程支持GBK文本打印和16灯WS2812B。灯环由FPGA本地状态驱动，与主机应用和识别模型解耦；主机连接保持115200，打印输出使用独立9600串口。

配套固件须支持 `0x82` 文本提交、`0x83` 状态查询、`0x02` 状态应答、完整 GBK 字节对校验，并将打印 UART 配置为 9600。仅支持轨迹和字符回传的固件无法处理打印任务，查询会超时；已有 ASCII 打印固件会拒绝中文并回复 `BAD_TEXT`。更新打印校验、分频或引脚后，需要重新构建位流并检查相应时序报告；旧构建的验证结论不覆盖新固件。

可用 CH340 检查 FPGA 打印输出：3.3 V 兼容的 RX 接 GPIO0_3/A16，GND 共地，不连接 TX 或 VCC。观察端设为 **9600、8N1、无流控、GBK 解码**。例如使用 pyserial 自带终端（端口名替换为实际设备，Ctrl+] 退出）：

```cmd
python -m serial.tools.miniterm COM7 9600 --encoding gbk
```

应直接收到“小芽学习记录”或“小芽自由书写”及正文，不含A5 5A外壳。按 UTF-8 解码会产生乱码，不代表打印字节错误。界面“已发送”/`SENT`只指FPGA打印UART最后停止位完成，**不代表实际出纸成功**。超时/断线不自动补发，先核对纸张/接收内容再决定是否新建任务。

独立提交工具在**项目根目录**运行，不与游戏同时占用串口：

```cmd
python -m orange_pi_game.print_link COM3 --text "中文测试 ABC123"
```

该命令连接 FPGA 的 **115200 主机口**，不是直接连接打印机。`print_link.py` 的 `--monitor` 同样固定为 115200，不适用于 9600 打印输出；后者使用上述 miniterm 或串口助手。日常使用只需启动游戏，无需独立提交工具。

<a id="print-protocol"></a>

### 打印扩展协议

#### 兼容与职责

- 主机连接仍为115200、8N1、无流控，复用现有连接，不增加香橙派到FPGA的线。
- 与上行`0x01`轨迹帧和下行`0x81`字符结果帧共存，不改变其格式。
- 消息按type分流，打印状态不输入模型或课程判题；DONE表示字符回传完成，不表示答题正确。
- 游戏后台仍独占串口。独立链路工具与游戏不能同时打开同一端口。
- 主机决定打印内容；FPGA校验、缓存、转发。文本固定GBK，兼容原可见ASCII，不携带E10初始化、切纸或任意ESC指令。

#### 公共帧

```text
A5 5A | version type seq count length_lo length_hi | payload | crc_lo crc_hi
```

`version=01`。CRC16初值FFFF、多项式1021、不反射、无最终异或；覆盖version到payload，CRC低字节先发。长度是payload字节数，不包含头或CRC。

| 方向 | type | count | payload长度 | 用途 |
| --- | --- | --- | --- | --- |
| FPGA→主机 | 01 | 40 | 128 | 原64点轨迹，不变 |
| 主机→FPGA | 81 | 01 | 1 | 原ASCII结果，不变 |
| 主机→FPGA | 82 | 01 | 5～516 | 提交文本转发任务 |
| 主机→FPGA | 83 | 01 | 4 | 查询任务状态，不启动转发 |
| FPGA→主机 | 02 | 01 | 7 | 转发任务状态 |

打印消息采用一次请求、一次应答，不流水堆叠请求。状态与轨迹按完整帧仲裁，不能将两类数据按字节交错输出。

##### 82：提交

```text
job_id[4字节，小端] + text[1～512字节]
```

任务ID为非零32位数，与8位轨迹seq无关。每个新任务使用新ID；seq仅用于关联单次请求/应答，可回绕。

文本固定采用 **GBK**：单字节允许`20～7E`可见ASCII、TAB=`09`、LF=`0A`、CR=`0D`；双字节首字节为`81～FE`，尾字节为`40～FE`且不等于`7F`。孤立首字节、非法尾字节以及ESC/NUL/DEL等控制字节整票拒绝，不先输出部分文本。

主机使用严格GBK编码；FPGA只检查字节结构，不查完整中文字库、不自动辨别UTF-8等错误编码。不能把UTF-8字节当GBK提交。超长不截断，直接拒绝；长度与CRC均按实际编码字节计算。协议本身不自动加换行；独立工具追加CRLF，因此正文上限为510字节，不是510个汉字。

FPGA只在整帧格式、文本和CRC均通过后开始输出。坏CRC/非法长度/半帧不会开始转发；不完整帧连续1秒无字节后丢弃。停止位错误中止未提交帧，不取消正在输出的任务。

##### 83：查询

payload仅为4字节任务ID。查询不会打印，也不会改变当前任务。应答回显本次查询的seq，不是原提交seq。

##### 02：应答

```text
job_id_LE32 + status_U8 + accepted_length_LE16
```

| status | 名称 | 含义 |
| --- | --- | --- |
| 00 | UNKNOWN | 设备没有该任务记录，可能未接收、已复位或历史已覆盖 |
| 01 | ACTIVE | 整帧已接受，正在向独立UART输出 |
| 02 | SENT | 最后一个字节的停止位已发完；**不是打印机出纸成功** |
| 03 | BUSY | 正在处理其他任务，本次未接受 |
| 04 | BAD_TEXT | CRC正确但文本含禁止字节或GBK结构不完整，本次未接受 |
| 05 | ID_CONFLICT | 最近任务ID相同但长度/载荷CRC指纹不同，拒绝 |

ACTIVE/SENT的长度须等于所提交文本字节数，其余状态长度为0。状态帧只由完整有效请求产生；CRC错误、超长头、任务ID=0等丢弃，不对不可信ID发应答。

#### 生命周期与失败处理

1. 主机只发一次82；设备接受后回复ACTIVE。
2. 主机约每250ms发83，直到SENT或错误；设备不主动推送完成消息。
3. 默认5秒未确定结果则显示`TIMEOUT_UNKNOWN`，不自动重发82。
4. 断线/退出将未完成任务标为`DISCONNECTED_UNKNOWN`，重连不自动补打。
5. BUSY表示任务未被接受，结束该次提交；再次提交需人工确认，不自动排队或重印。

FPGA只保存**最近一个任务**的ID、长度与载荷CRC16指纹：同ID同指纹的重复提交只回复状态、不重复输出。CRC16不是密码学内容校验；不同内容理论上可能碰撞。去重记录在复位或后续新任务覆盖后失效，不提供跨复位或跨任务的“恰好一次打印”保证。主机采用新随机非零ID，不使用固定轨迹seq替代任务ID，不因超时盲目重发。

已接受的任务不因清空笔迹而取消。S0复位会中止输出并清空设备内任务记录，纸上可能保留部分正文。缺纸、缓冲忙、掉电和实际打印完成未接入反馈，UART状态不能替代这些状态。

#### 黄金帧

任务ID=1、文本`HELLO\r\n`，seq=0：

```text
A5 5A 01 82 00 01 0B 00 01 00 00 00 48 45 4C 4C 4F 0D 0A F6 C2
```

ACTIVE应答：

```text
A5 5A 01 02 00 01 07 00 01 00 00 00 01 07 00 AD A3
```

seq=1查询任务1：

```text
A5 5A 01 83 01 01 04 00 01 00 00 00 2D 93
```

SENT应答：

```text
A5 5A 01 02 01 01 07 00 01 00 00 00 02 07 00 B4 22
```

独立转发口只输出`48 45 4C 4C 4F 0D 0A`，不输出A5 5A、任务ID或状态封装。

#### 主机接口

[serial_protocol.py](serial_protocol.py)提供共享编解码、流式解析和事务状态机。[print_link.py](print_link.py)提供独立验证命令。二者不依赖pygame或模型；真实串口仅需要已有pyserial。

游戏中的手动打印按钮调用`PenInput.request_print(text)`，通过队列交给唯一串口线程；`snapshot()`附带`print_state / print_job_id / print_message`。确认时只提交一次，界面逐帧读取状态不会重复发送；同一时刻只允许一个未完成任务。未连接FPGA时提示不可用，不崩溃或假报发送成功。新状态帧不产生识别字符、得分或喵声。

打印机控制指令以设备厂商手册为准；文本转发协议不提供任意厂商命令透传。

## 常见问题

### 部署检查

1. 启动应用并选择 FPGA 主机口，确认首页可显示且没有串口错误。
2. 写一个字符并确认，检查主机收到识别结果，FPGA 从 WAIT 进入 DONE；清空后可继续书写。
3. 分别完成数字与单词课程，检查混写解锁；重新启动后检查解锁、星星和黑板内容保留。
4. 完成两组不同练习，在档案中检查汇总与两条独立记录的题目、日期和成绩。
5. 使用兼容打印固件时，先打印短黑板文本，再选择一条学习记录打印；检查取消不输出、预览与纸张内容一致，打印后仍可正常书写。

### 排错

| 现象 | 检查 |
| --- | --- |
| 缺少Python模块 | 是否使用安装依赖的同一个环境 |
| 模型/导入文件缺失 | 是否保留完整运行目录 |
| 串口打不开 | 实际端口、权限及是否被其他程序占用 |
| 本地无画面 | 先用`--windowed`，确认图形桌面会话 |
| 切换中英文 | 首页写6并确认，或点击语言按钮；中文需要系统中文字体 |
| 中文字体缺失 | 安装系统中文字体，或用高级入口`--font`选择已有字体；程序不会自动下载 |
| FPGA一直WAIT | 检查串口服务、坏CRC/线程错误日志；恢复后清空重写 |
| 页面自动变化 | 是否误用高级回放入口，或收到实际确认轨迹 |
| 档案不恢复 | 路径、可写权限及“存档不可用”提示，先备份再处理 |
| 预览正常但打印查询超时 | 固件是否支持82/83/02扩展，主机口是否为115200 |
| 打印机乱码或不出纸 | 打印口9600/8N1、GBK字库与解码、TTL接口、电平、供电与装纸方向 |
| 小票行序与预览相反 | 核对是否更新游戏app.py及实际出纸方向；游戏已针对新行出现在旧行上方补偿，不要再叠加打印机方向切换 |
| 中文任务返回BAD_TEXT | 是否仍使用只接受ASCII的旧打印固件 |
| 正文被印成十六进制 | 是否仍在自检后的DUMP模式；不按键断电重启 |
| 提示已发送但没有纸张输出 | SENT只表示UART发送结束，不包含打印机缺纸或完成反馈 |

### 验证范围与限制

- 基础游戏已在 Windows 和香橙派 Linux 环境运行验证。软件检查覆盖 Python 3.9 语法兼容、协议与虚拟串口、学习档案、打印事务和离屏页面。
- E10已在本项目配置下通过香橙派应用→FPGA→打印机的GBK整机打印测试，行序补偿后内容和行序正常。
- 仅支持 GBK 中文与 ASCII 短文本，不支持UTF-8、表情、图像、自动裁纸、打印字体设置或硬件流控；状态未知时不自动重印。
- 模型识别受字形、笔顺和输入噪声影响；课程成绩不是独立识别准确率评测。
- 主机应用不修正摄像头极边缘漂白，也不验证 FPGA 的真实 PCLK 时序；相关边界以配套 FPGA 工程说明为准。
