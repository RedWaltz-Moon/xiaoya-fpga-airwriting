# 小芽 · FPGA 空中书写学习系统

用红笔或戴手套的食指在空中书写，由 FPGA 采集轨迹，Windows / 香橙派识别字符并驱动数字与英文学习应用。

本项目由实时视觉终端、62类轨迹分类器和交互学习应用组成。FPGA HDMI 显示摄像头与调试画面；香橙派 HDMI 显示学习界面。两路显示独立，串口只传确认后的轨迹，不传实时视频。

自研代码、人工采集轨迹、模型及维护者提供的OLED彩虹猫字模采用 [MIT License](LICENSE)，作者 **RedWaltz**。高云生成IP、厂商参考代码、外部词库及第三方软件依赖保留各自授权，详见文末说明。

## 系统架构

```text
OV5640 摄像头
    ↓
FPGA：PEN / HAND 检测 → 轨迹缓存 → 确认 → 归一化、64点重采样
    │                                           │
    └→ DDR3帧缓冲 → FPGA HDMI 实时监看          UART
                                                ↓
                                  主机：字符识别 → 学习游戏 → 主机HDMI
                                                │
                                   单字符结果回传┘
                                                ↓
                              FPGA：字符回显 / OLED猫互动 / 喵声
```

### 主要功能

- **两种输入**：PEN 红笔头书写；HAND 佩戴绿手套，单食指书写、比耶确认、张掌清空。
- **轨迹识别**：数字、大小写英文字母共62类，CPU + NumPy 推理，无需 YOLO、GPU 或 NPU。
- **学习游戏**：数字练习、单词练习、混写挑战、自由拼词 / 电子黑板、学习档案。
- **练习反馈**：直观提示、成功反馈、星星、通关记录、跨启动错题复习；6089个单词，包含基础生活词与四六级词表中的常用词，按词长逐步进阶。
- **板载交互**：物理按键、红外遥控、OLED 彩虹猫、八位数码管、LED、摄像头 FPS 和开机局部自检。
- **声音反馈**：FPGA 收到合法字符回传后播放一声柔和合成“喵”；不区分游戏答题正确或错误。
- **状态灯环**：16灯WS2812B，启动蓝跑、PEN青呼吸、HAND紫呼吸、WAIT黄跑、回传绿灯、打印白跑、故障红闪。
- **学习小票**：E10 TTL打印机，黑板内容或所选单次练习的日期、成绩与错题；中文/英文随界面切换。

FPGA 不运行字符模型、不保存整词；游戏不区分 PEN/HAND，均接收同一种64点轨迹。

## 快速开始

### 1. 准备硬件

| 项目 | 参考配置 |
| --- | --- |
| FPGA | ACG720，GW5AT-138C，`GW5AT-LV138PG484AC1/I0` |
| 摄像头 | OV5640，8位DVP，RGB565，1280×720 |
| FPGA工具 | Gowin V1.9.12，匹配 `gw5at138c-007` 的生成IP |
| 主机 | Windows电脑，或香橙派 AI Pro / Ubuntu 22.04.3 LTS |
| 主机串口 | USB-TTL，3.3V，115200 / 8N1，无流控 |
| 显示 | FPGA HDMI监看屏幕；主机HDMI学习界面 |
| 可选OLED | SSD1306，128×64，I²C地址 `0x3C` |
| 可选灯环 | 16颗WS2812B，开发板5V电源接口供电、适当的数据电平匹配 |
| 可选打印机 | 雀印 / 荣达RD-E10低压TTL版，开发板5V电源接口供电，9600 / 8N1 |
| HAND环境 | 绿手套、稳定照明，避免同色目标干扰 |

UART：FPGA TX / M15 接主机 RX，FPGA RX / J21 接主机 TX，共地。不能直接接 RS-232 电平。

OLED：GPIO0_0 / A13 → SDA，GPIO0_1 / A14 → SCL；BANK 和供电采用3.3V，不能将 SDA/SCL 上拉到5V。球号不等于排针编号，完整映射见[工程约束](acg720_dvp_ov5640_hdmi/src/acg720_dvp_ov5640_hdmi.cst)。

灯环：GPIO0_2 / A15 → DIN；打印：GPIO0_3 / A16 → E10 TTL RX。两种外设均由开发板5V电源接口供电并与FPGA共地，GPIO0保持3.3V，不把5V或打印机TX接回FPGA。灯环优先采用AHCT单向电平转换；接线、电源及全部灯效见[FPGA说明](acg720_dvp_ov5640_hdmi/README.md#wiring)。

### 2. 编译与下载 FPGA

1. 在 Gowin 打开 [GPRJ](acg720_dvp_ov5640_hdmi/acg720_dvp_ov5640_hdmi.gprj)。
2. 显式设置顶层与输出基名为 `acg720_dvp_ov5640_hdmi`，核对138C器件。
3. 完整综合、自然布局布线，检查 ERROR 和 Setup/Hold；不要只对旧网表重跑 P&R。
4. 下载 `acg720_dvp_ov5640_hdmi/impl/pnr/acg720_dvp_ov5640_hdmi.fs`，检查生成时间、器件及线缆。
5. 接 FPGA HDMI1，检查摄像头、自检、OLED和数码管；音频测试先调低屏幕音量。

SRAM 下载掉电失效；持久启动按板卡 Flash 流程配置。完整复制 `src/`，不要遗漏生成IP的包含文件、字模及音频 `.mem`。其他板卡不能直接使用本位流，138B器件IP也不能直接替代138C。

### 3. 准备主机环境

正式运行需要 Python、NumPy、pygame、pyserial。参考实测环境为 Windows Python 3.12.9 / pygame 2.6.1，以及香橙派 Python 3.9.2 / NumPy 1.26.4。采集与训练推荐 Python 3.10+。

先在准备运行的同一 Python 环境检查：

```bash
python3 --version
python3 -c "import pygame, numpy, serial; print('依赖检查通过')"
python3 -m serial.tools.list_ports
```

Windows 将 `python3` 换成 `python`。缺少依赖时可按自己的环境安装：

```bash
python3 -m pip install numpy pygame pyserial
```

中文界面需要系统中文字体，例如文泉驿字体；缺失时会使用英文回退。Linux桌面需要可用显示会话，串口用户需有设备访问权限。

### 4. 启动游戏

在项目根目录执行：

```bash
# Windows
python orange_pi_game/start.py --windowed

# 香橙派 Linux
python3 orange_pi_game/start.py --windowed
```

也可进入 `orange_pi_game/` 后执行 `python3 start.py --windowed`。启动会列出可用串口，选择 FPGA 对应端口；端口选择需要终端输入，进入游戏后可使用空中书写完成页面操作。

默认加载随附基线模型并开启 B/D 笔形复核。界面使用1920×1080设计画布，窗口初始1280×720、按比例缩放。香橙派本地图形桌面已使用窗口模式运行；不需要强行使用全屏。

游戏自行接收、推理与回传，**不要同时运行串口助手、固定A工具或独立推理服务**。

### 最小运行包

保持 `orange_pi_game/`、`tools/`、`models/` 同级。保留游戏11份Python文件（`start`、`__init__`、`app`、`core`、`vocabulary`、`vocabulary_cet`、`rendering`、`live_input`、`serial_protocol`、`learning`、`replay`）、`tools/trajectory_infer/pen_uart_reply.py` 和基线 NPZ，共13个运行文件，另附 LICENSE。独立打印链路验证另需可选的`print_link.py`。

`replay.py` 仍是导入依赖，不应因为不使用回放而删除。数据、训练工具和验证报告不是游戏运行依赖；只复制游戏目录也不能独立运行。

## 书写与板载操作

上电默认 PEN。红外数字1～4替代 S1～S4，不替代复位键 S0。

| 控制 | PEN | HAND |
| --- | --- | --- |
| S0 | 全系统复位 | 全系统复位 |
| S1 / 红外1 | 切HAND并清空当前轨迹、结果 | 切PEN并清空当前轨迹、结果 |
| S2 / 红外2 | 原画 / 红像素调试 | 原画 / mask、指尖、手势调试 |
| S3 / 红外3 | 清空轨迹、结果 | 放松绿色优势门限 |
| S4 / 红外4 | 确认并发送 | 收紧绿色优势门限 |
| 单食指 | — | 书写 |
| 比耶 | — | 确认并发送 |
| 五指张掌 | — | 清空轨迹、结果 |

HAND动作需连续稳定6帧，连续无手6帧重新武装；握拳不作为书写或确认动作。门限在场消隐更新，复位恢复、不掉电保存；通常保持默认，过度放宽会增加噪声。

每个字符：书写 → 确认 → WAIT → 主机回传 → DONE → 清空 → 下一字符。确认后轨迹冻结；原地抖动或无效短轨迹不会有效发送，但仍需清空重写。普通画面显示黄色轨迹，调试画面不叠加轨迹。

板端只显示一个回传字符；主机负责单词、游戏进度和学习记录。新合法回传触发OLED猫互动和喵声，无论游戏答案对错；重复确认不重复发送或喵。屏幕音量用于调节声音。

OLED开机完整检查页结束后回 MODE / STATE / 猫页，整屏旋转180°并左右镜像用于棱镜展示。数码管显示上电计数 `DD.HH.MM.SS`，不是实时时钟。HDMI左下 `CAM xx FPS` 是摄像头帧率，不能将720p60输出刷新率当摄像头帧率。

## 学习页面与无键鼠交互

| 首页输入 | 页面 | 内容 |
| --- | --- | --- |
| 1 | 数字练习 | 每组10题，0～9各一次，顺序随机；气球落到底部后等待，不因写得慢扣分 |
| 2 | 单词练习 | 每组3词、合计不超过20个字母；中文释义，按首字母大写、中间小写逐字符练习，如 `Cat` |
| 3 | 混写挑战 | 三个数字与三个完整单词交替，合计最多20个字符；数字和单词各通关至少一次后解锁 |
| 4 | 自由拼词 / 电子黑板 | 累积字符、空格、换行、删除，保存文本与最近确认轨迹 |
| 5 | 学习档案 | 默认汇总，另有逐次学习记录、日期成绩与单条小票打印 |
| 6 | 中文 / English | 首页切换界面及小票语言；不改变题目、成绩或黑板原文 |

词库包含6089词：1055个3～4字母词、5034个5～10字母词。以308个生活词为基础，合并公开CET-4/CET-6词表中的纯字母词条；重复词采用生活词表的释义，不包含超过10字母的词、短语或带连字符的词。

单词课与混写仍每第三组最多加入一个长词，词长上限从6开始，每三次通关增加2，最高10；结合近期记录降低重复，并安排错题复习。长词显示、学习档案及小票使用同一词库，升级无需清空已有档案。词表来源、筛选规则与许可证见[应用说明](orange_pi_game/README.md#vocabulary)。

游戏仅对 `C/c、S/s、O/o、Z/z` 使用题目匹配容错，其余大小写严格区分，数字0不等于字母O。容错不修改模型预测、串口回显或日志。

- 练习中，当当前目标不是0时，8秒内两次独立确认0返回首页；目标为0时优先判定答案。
- 完成页：1再练一次、2返回首页、3打印学习小票（再用1发送 / 2取消）。暂停页：1继续、2返回首页。
- 黑板：0打开工具；1删除、2空格、3换行、4清空（再用1确认 / 2取消）、5首页、6输入实际数字0、7打印内容（再用1发送 / 2取消）；0关闭工具。
- 学习档案：默认查看汇总；1数字复习、2单词复习、3练习记录、0首页。历史页1～4选中一条、5打印、7/8翻页、0返回汇总，再用1确认发送或2取消。

板端“清空轨迹”不会删除黑板文本。黑板最多120字符、界面显示末尾4行；游戏不接收视频，也不采用等待120秒才判定单词的流程。页面详细规则见[应用说明](orange_pi_game/README.md)。

## 数据、训练与推理

### 模型类型

当前模型是 **1-NN 最近模板分类器**，不是深度学习网络。FPGA输出64×2归一化整数坐标；软件除以255、展平为128维特征，以均方距离寻找最近训练模板。每类分数是负距离，不是概率或校准置信度。

“训练”是检查人工标签数据、构建模板库、验证并保存 NPZ；没有 epoch、反向传播或优化器。B/D复核只在初始预测为大写B或D时，用8×8空间直方图在两者之间重选。

| 数据 / 策略 | 数量 / 结果 |
| --- | --- |
| 训练，p01 / PEN / tr01 | 930笔，每类15笔 |
| 验证，p01 / PEN / val01 | 310笔，每类5笔 |
| 原始最近模板，严格62类 | 283 / 310，91.29% |
| 开启B/D复核，严格62类 | 288 / 310，92.90% |

两种策略均有21次仅大小写互换错误。验证集已用于选型，不是未见过的最终测试集；这些数字不代表跨人、HAND或不同光照的准确率。

PEN/HAND可共用现有模型，因为输入协议没有模式字段。但模板来自PEN，没有独立HAND准确率报告；当前加载器接受PEN或未标模式的模型，不接受新训练的HAND标记模型。两份随附NPZ字节相同，文件名含 `bdshape_probe` 不会自动开启复核，开关是 `--bd-shape`。

### 采集新场次

所有工具命令从项目根目录执行；Linux可换成 `python3`。

```bash
python tools/trajectory_collect/collect.py data/full/train/pen_p01_tr02.jsonl --writer p01 --session tr02 --mode PEN
```

选择串口 → 等待FPGA确认轨迹 → 人工输入真实标签 → 回车保存 → 等待下一笔。同文件、同参数可续采；FPGA复位使seq归零，但不重置保存计数。数据不是游戏预测日志。

### 训练与独立实写验证

```bash
python tools/trajectory_train/train.py --mode PEN --train data/full/train/pen_p01_tr01.jsonl --val data/full/val/pen_p01_val01.jsonl --output models/pen_new_62.npz --report models/pen_new_62_report.json --bd-shape

python tools/trajectory_infer/pen_uart_reply.py COM3 --model models/pen_new_62.npz --bd-shape
```

COM3换成实际端口。训练输出必须不存在，脚本拒绝覆盖；训练与验证需完整62类、不同场次、无完全相同的跨集轨迹。验证数据不会进入模板库。测试新模型不会自动替换游戏默认模型。

采集、训练、推理三份脚本各自完整自包含，可分别复制运行，通过 JSONL / NPZ 交接。详细参数见[采集](tools/trajectory_collect/README.md)、[训练](tools/trajectory_train/README.md)、[推理](tools/trajectory_infer/README.md)。

## UART接口

115200、8N1、无硬件流控。V1帧中长度与CRC均低字节在前：

```text
上行138字节：A5 5A 01 01 seq 40 80 00 [x0 y0 ... x63 y63]  crc_lo crc_hi
下行 11字节：A5 5A 01 81 seq 01 01 00 ascii                crc_lo crc_hi
```

- 上行64点，坐标0～255；下行单个 `0–9 / A–Z / a–z` ASCII字符。
- CRC16：初值FFFF、多项式1021、不反射、无最终异或，覆盖version到载荷，不含A5 5A。
- seq是8位单次确认关联号，会回绕、复位归零，不是采样计数或永久事件ID。
- 主机回传原seq；上行发送完毕后开放接收窗口，合法格式、CRC与当前seq匹配才进入DONE。清空、切换会使旧结果失效。
- 无模式、答题正误、ACK、复位通知或整词边界字段；不直接回传字符串。

seq=0、结果A的示例：`A5 5A 01 81 00 01 01 00 41 4E C1`。

[E10打印扩展](orange_pi_game/README.md#print-link)支持黑板、课程完成页与历史单次记录。学习档案默认显示汇总；打印时选择一次练习，预览后确认。小票语言跟随中英文界面，首页写`6`并确认切换；GBK文本按32西文列/16汉字排版，保留所选练习的原日期、题目和成绩，不合并其他记录，不扩展原有62类字符识别范围。

游戏预览按正常阅读顺序显示；打印出口针对实机逐行自下向上的出纸方向倒序发送已排版的行，行内字符和GBK编码不倒转。该适配只在主机完成，FPGA协议不变；实际纸面方向仍需与所用打印机设置核对。

随附[FPGA工程](acg720_dvp_ov5640_hdmi/README.md)已包含`0x82`提交、`0x83`查询、`0x02`应答及GBK字节对校验：主机通信仍为115200，独立打印口GPIO0_3/A16为9600。只接受ASCII或未接打印扩展的旧位流不兼容，必须从当前源码重新构建；仅更新主机应用不能升级板端固件。灯环由FPGA本地状态驱动，不增加主机协议或运行依赖。

E10已在本项目配置下通过香橙派应用→FPGA→打印机的GBK完整链路测试，行序补偿后打印正常。`SENT`只表示FPGA打印UART发送结束，不代表纸张输出成功。兼容要求、接线、排版与排错见[应用打印说明](orange_pi_game/README.md#print-link)。

主机使用独立事件ID避免seq回绕影响计数；短时重复帧不会重复计入游戏。串口断线恢复后清空重写。软件写出回传不等于FPGA已接收，板端DONE才是实际闭环观察点。

## 验证与工程边界

### 功能验证

1. 检查Python依赖、串口和中文字体，启动窗口界面。
2. 上电 / S0：摄像头画面、开机检查、OLED正常页、FPS、数码管正常；无回传不自动喵。
3. PEN写一个字符并确认：WAIT → DONE、绿色回显、猫互动、一声喵；重复确认不重发，清空后可继续。
4. HAND单食指书写、比耶确认、张掌清空；握拳不应产生有效书写或确认。
5. 验证首页数字导航、单词大小写容错、混写解锁、黑板工具和跨启动学习记录。
6. 测试短轨迹、模式切换、红外、断线恢复及连续书写，保留异常日志。
7. 确认16颗灯均参与灯效、跑马覆盖最后4颗；打印短黑板文本和一条学习记录，检查整字、行序、取消与不重复打印。

基础系统已在参考硬件上完成功能验证。上述流程用于复现主要功能；不同源码配置、工具版本和硬件组合需要独立验证，功能测试不能替代长期可靠性评估。

16颗WS2812B灯环已在本项目配置下通过实机功能测试。历史时序报告仅适用于其对应源码与构建。

### 参考构建

2026-10-09，Gowin V1.9.12、138C、默认输出名、自然P&R：综合/P&R无ERROR；当前约束Setup/Hold违规0/0，最差+1.506/+0.141ns；HDMI Fmax83.596MHz（约束74.25MHz）；逻辑16103、寄存器8756、BSRAM51、DSP4、I/O94。详细指纹与报告口径见[FPGA说明](acg720_dvp_ov5640_hdmi/README.md#limitations)。

### 已知限制

- **摄像头时钟约束**：历史估计PCLK约87.5MHz，而SDC约束50MHz。当前零违规仅对应现有约束，实际摄像头时钟条件下的完整时序闭合尚未验证；PR1014通用时钟路由风险仍在。
- HAND使用绿手套并需要合适照明；同色背景干扰、极边缘漂白、轮廓噪声与手势误判仍可能影响体验。当前使用8槽空间候选筛选，未实现完整连通域合并。
- 公共缓存最多256点；无效短轨迹确认后须清空。极快清空再确认有旧帧生命周期理论竞态；V1没有ACK或自动重传保证。
- 最近模板受笔顺、字形和输入噪声影响，没有通用未知字符拒识；游戏容错不等于模型解决所有大小写歧义。
- HDMI固定720p60 / 48kHz音频，无EDID协商、HDCP或接收ACK，不保证所有屏幕兼容。喵声为合成素材，不是真猫录音。
- HDMI存在偶发无信号的已知问题，触发与恢复机制尚未定位；当前实现未提供失锁超时自动重启。
- 开机DDR自检仅16KiB两轮写读，不是全容量测试；内部HDMI扫描正常不证明显示器连接。没有完整RTL仿真或定量长稳统计。

## 实现经验与排错

| 现象 / 设计点 | 处理原则 |
| --- | --- |
| CT1135大量约束端口不存在 | 核对顶层，重新综合再P&R；不靠删除CST掩盖错误 |
| 修改后仍是旧画面 | 检查完整编译、位流时间、器件和下载路径 |
| 一直WAIT | 排查端口占用、线序、协议、CRC与seq，恢复后清空重写 |
| 原始手指已经变白，mask消失 | 先检查照明与曝光影响；原图丢失色彩不能单靠阈值恢复 |
| 显示或检测长组合路径 | 同拍预解码、窄位索引、同步RAM读延迟配齐；不滥用false_path隐藏违规 |
| 轨迹/模式跨时钟域 | 事件同步、稳定快照与明确生命周期，不能只同步多位数据各个bit |
| 香橙派本地全屏无画面 | 使用已验证的 `--windowed`，检查图形会话；不视为模型或串口故障 |
| OLED不亮 / 喵声过大 | 检查3.3V、地址与接线；声音在屏幕侧调节 |
