# FPGA 空中书写采集与交互终端

基于 Gowin GW5AT-138C 的实时视觉终端，让笔尖与指尖成为交互输入。

本工程在 ACG720 开发板上实现摄像头采集、PEN/HAND 检测、轨迹处理、UART 通信及板载交互，并提供 E10 热敏打印与16灯 WS2812B 状态灯环。配合主机识别应用，可完成“空中书写 → 字符识别 → 显示回传 → 声光反馈 → 学习小票”的交互闭环。

FPGA HDMI 用于实时画面监看，香橙派或 Windows 主机负责识别和游戏显示。FPGA 不运行字符模型，也不保存完整单词。

> 目标器件为 GW5AT-138C；正式顶层与输出基名均为 `acg720_dvp_ov5640_hdmi`。其他板卡需要重新核对器件相关 IP、引脚与时序，不能直接下载本工程位流。

## 功能与架构

- PEN：红笔头检测、面积/形状候选筛选、检测框/质心与黄色轨迹。
- HAND：绿手套，单食指书写、圆点调试、比耶确认、张掌清空；握拳不作为确认或书写动作。
- 公共轨迹：确认时冻结，拒绝过短/近原地抖动，归一化重采样为64点，通过UART发送。
- 单字符回显：接受数字和英文字母ASCII，区分大小写，HDMI顶部亮绿色显示；清空/切换后消失。
- 板载周边：五键、HT6221红外1～4、八位595数码管、LED、SSD1306 OLED和彩虹猫互动。
- 工程化：开机DDR局部写读自检、健康监测、OLED完整检查后回正常页、HDMI左下摄像头FPS。
- HDMI音频：合法回传后约0.58秒合成喵，48kHz双声道16位LPCM；闲时静音，不判断游戏答题正误。
- 状态灯环：16颗WS2812B，显示启动、PEN/HAND、WAIT、回传、打印和故障状态，低亮度运行。
- 热敏打印：主机选择并排版学习小票，FPGA完整校验GBK文本后由独立9600串口发送，不占用原轨迹缓存。

```text
OV5640 → PEN/HAND视觉 → 公共轨迹/64点重采样 → UART → 主机识别/游戏
   └────────── DDR3帧缓冲 → FPGA HDMI监看               │
                                 ↑                     │
                       字符回显/OLED互动/喵声 ← UART结果┘
```

FPGA不运行模型、不保存完整单词。FPGA HDMI监看摄像头，主机HDMI显示游戏，两路独立；主机仅接收确认后的轨迹，不接收实时视频。

## 快速开始：编译与下载

本目录包含完整工程与当前编译产物，其中大型 `.pr` 布局数据库由Git LFS存储。获取全部文件需已安装Git LFS，然后执行：

```bash
git clone https://github.com/RedWaltz-Moon/xiaoya-fpga-airwriting.git
cd xiaoya-fpga-airwriting
git lfs install --local
git lfs pull
```

GitHub网页生成的ZIP是否包含LFS对象取决于仓库设置；需要完整布局数据库时，使用上述方式获取。

1. Gowin打开本目录`acg720_dvp_ov5640_hdmi.gprj`，检查138C型号。
2. **显式设置顶层**为`acg720_dvp_ov5640_hdmi`，输出基名同名。不能留空让工具自动选择，也不能设成`video_720p_colorbar`。
3. 完整综合后自然布局布线；不要仅重跑旧/错误网表的P&R。重新打开工程，避免IDE旧配置覆盖新设置。
4. 日志必须显示`Current top module is "acg720_dvp_ov5640_hdmi"`；确认综合/P&R无ERROR及当前约束Setup/Hold违规为0。
5. 下载`impl/pnr/acg720_dvp_ov5640_hdmi.fs`，核对器件、线缆及文件时间。SRAM Program用于演示，掉电后需重新加载；持久启动另按板卡Flash流程配置。
6. FPGA HDMI1接监看屏幕，主机HDMI接游戏屏幕；音频测试先调低屏幕音量、选HDMI音源并取消静音。

默认灯环配置为16颗。更改灯数、UART参数或引脚后，应从对应源码完整执行综合与布局布线，避免混用不同配置的位流。灯环由FPGA独立驱动，不改变主机应用、模型或115200串口参数。

可清理`impl/gwsynthesis/`、`impl/pnr/`、`impl/temp/`的编译输出，但保留过程配置、src和GPRJ；清理后必须重新综合/P&R。个人IDE缓存和历史成功标记不属于发布依赖。

## 接线说明

以下球号来自[本工程CST](src/acg720_dvp_ov5640_hdmi.cst)。完整摄像头/DDR/HDMI映射以CST与板卡资料为准。**球号不是排针编号**，外接前核对丝印和排针映射。

| 信号 | 端口 / 球号 | 接线 |
| --- | --- | --- |
| UART TX | `uart_tx` / M15 | 接主机/USB-TTL RX |
| UART RX | `uart_rx` / J21 | 接主机/USB-TTL TX |
| OLED SDA | `oled_sda` / A13，GPIO0_0 | 接SSD1306 SDA |
| OLED SCL | `oled_scl` / A14，GPIO0_1 | 接SSD1306 SCL |
| 灯环数据 | `ws2812_dout` / A15，GPIO0_2 | 经适当电平匹配接WS2812B **DIN** |
| 打印输出 | `printer_uart_tx` / A16，GPIO0_3 | 接E10 TTL RX，9600 / 8N1 |
| 红外输入 | `ir_rx` / F21 | 板载接收 |
| 数码管数据 | `SEG7_DIO` / M18 | 595数据 |
| 数码管锁存 | `SEG7_RCLK` / C2 | 595锁存 |
| 数码管时钟 | `SEG7_SCLK` / F4 | 595移位 |

UART/OLED使用3.3V电平，TX/RX交叉、共地。OLED建议VCC接3.3V，确认GPIO0 BANK电压为3.3V。即使模块支持5V供电，也不要将SDA/SCL上拉至5V后直接接FPGA；不使用RS-232电平直接连接。

灯环和打印机均由**开发板的5V电源接口**供电，并与FPGA共地。GPIO0仅传输数据信号，外设电源不接GPIO信号脚、3.3V引脚或CH340供电脚。打印机TX不接FPGA，当前没有缺纸或打印完成反馈。

**GPIO0 BANK始终保持3.3V。** 5V灯环是否可靠识别3.3V数据取决于灯珠修订和接线；已能点亮不等于所有模块都兼容。推荐用5V供电的74AHCT125等单向缓冲将数据升至5V；普通74HC125不能直接视作等价替代。DIN可串100～330Ω电阻，但电阻不是电平转换；灯环DOUT、5V电源和打印机TX均不得直接回接FPGA信号脚。

## 操作指南

上电默认PEN、普通画面；S0～S4低有效。红外数字1～4对应S1～S4，不模拟S0。

| 按键 / 球号 | PEN | HAND |
| --- | --- | --- |
| S0 / F15 | 全系统复位 | 全系统复位 |
| S1 / A20，红外1 | 切HAND，清当前轨迹/结果 | 切PEN，清当前轨迹/结果 |
| S2 / B20，红外2 | 原画 ↔ 红像素调试 | 原画 ↔ mask/指尖/手势调试 |
| S3 / A21，红外3 | 清空轨迹/结果 | 放松绿色优势门限 |
| S4 / B21，红外4 | 确认并发送 | 收紧绿色优势门限 |

两种模式分别保存S2开关。HAND门限运行时调整、复位恢复、不掉电保存，通常保持默认值；过度放宽会引入噪点。

HAND使用绿色手套：单食指书写、比耶确认、张掌清空。手势连续稳定6帧生效，连续无手6帧重新武装，同一姿势不持续触发。HAND的S4不是发送键，也不提供裸手/红手套模式。

普通画面有黄色轨迹；S2调试画面不叠加黄色轨迹。PEN框/中心及HAND指尖圆点用于调试。确认后轨迹冻结，必须清空再写；无效短轨迹确认后也需清空重写。

<a id="status"></a>

## 状态与周边

| 状态 | 含义 | 操作 |
| --- | --- | --- |
| DRAW | 可写/等待确认 | 完成字符后确认 |
| WAIT | 有效轨迹已发送，等待结果 | 检查主机服务，故障恢复后清空重写 |
| DONE | 合法同序号结果已接收 | 查看后清空，写下一字符 |

同一笔迹不应重复发送；DONE时重复确认保留结果、不再次喵。新的合法回传触发OLED猫互动及喵声，与答题正误无关；清空/切换本身不触发声音，但已入队短音可能播至清空之后。S0/PLL失锁清音频队列。

- OLED：完整开机检查页显示终态后回MODE/STATE/猫页，S0重启检查。UART未有第一次回传的WAIT不算开机失败。整屏180°旋转及左右镜像为棱镜展示设计，普通直视方向可能不符合习惯。
- HDMI：健康信息、左下摄像头FPS；不把60Hz显示刷新率当采集帧率。
- 数码管：`DD.HH.MM.SS`上电运行计数，S0归零，不是实时时钟或学习档案。
- LED：`led[0..2]`为PLL锁定、DDR校准、首帧就绪；`led[3]`为帧缓冲/自检故障汇总。LED4初始化、LED5帧心跳、LED6已见像素、LED7摄像头超时。

DDR自检仅16KiB两轮写读，不等于全容量测试。HDMI内部扫描OK不证明屏幕连接，OLED猫互动不证明屏幕收到音频。

### WS2812B 灯效

| 板端状态 | 16灯灯效 |
| --- | --- |
| 启动检查 | 蓝色跑马 |
| PEN可书写 | 青色呼吸 |
| HAND可书写 | 紫色呼吸 |
| WAIT | 黄色跑马 |
| 合法字符回传 | 绿色较亮约0.8秒，随后低亮保持，清空后恢复书写状态 |
| 打印UART发送中 | 白色跑马，结束后返回原状态 |
| 自检FAIL | 红色闪烁 |

故障、启动、打印、回传、等待、书写按此顺序优先显示。灯色不区分游戏答题正误，打印灯也不表示纸张输出成功；清空或切模式不会取消已接受的打印任务。

灯环每20ms提交一次完整颜色快照，跑马约100ms移动一灯，沿DIN到DOUT级联方向覆盖0～15号；每通道最大8/255，呼吸范围1～8。控制器统一末灯编号，再传给串行器，跑马、尾点和发送长度不会各自使用不同灯数。

发送使用既有50MHz时钟、GRB高位先发，每帧16×24=384位；每位64拍，0高/低为320/960ns，1高/低为680/600ns，跨灯取数多20ns低电平，帧间低350µs。含取数和锁存约0.842ms，低于20ms刷新间隔；不增加时钟域、BRAM或厂商IP。参数依据[Worldsemi WS2812B-V5/W手册](https://datasheet.lcsc.com/datasheet/pdf/3795cfb9d54f7ec8ecc0b043ede3c05a.pdf?productCode=C2874885)，不同修订仍需核对。

S0按住期间仅将数据线拉低，不能保证已锁存灯色立即熄灭；释放后先发送一帧全黑，再恢复状态灯效。

## UART 协议

115200波特率、8数据位、无校验、1停止位、无硬件流控。格式为十六进制字节，长度和CRC低字节先发：

```text
上行：A5 5A 01 01 seq 40 80 00 [x0 y0 ... x63 y63]  crc_lo crc_hi
下行：A5 5A 01 81 seq 01 01 00 ascii                crc_lo crc_hi
```

- 上行138字节，64点，每轴8位归一化坐标，载荷128字节。
- 下行11字节，仅一个ASCII数字/英文字母，支持大小写。
- CRC16初值FFFF、多项式1021、不反射、无最终异或，覆盖version至载荷，不含A5 5A。
- 8位seq关联本次确认，可回绕，复位归零正常；主机原seq回传，不使用累计采集数代替。
- 上行发完后开放接收；合法格式、CRC、同seq且处于接收窗口才进入DONE。清空/切换使旧结果失效。
- 无PEN/HAND模式、答题正误、ACK、复位通知或整词边界字段；不能直接发送字符串代替帧。

配套主机在其项目根目录使用 `python3 orange_pi_game/start.py --windowed` 启动；进入 `orange_pi_game/` 后则使用 `python3 start.py --windowed`。Windows 将 `python3` 替换为 `python`。详见主机应用的 `orange_pi_game/README.md`。主机与本工程可分别部署；同一串口不能同时由串口助手或第二个推理服务占用。

### 打印扩展

本工程已包含`0x82/0x83/0x02`消息、GBK结构校验和独立打印口。主机连接仍为115200，A16打印输出固定9600；两端均为8N1，不将主机串口降为9600。FPGA不生成小票内容、不知道当前课程或成绩，主机负责选择记录、日期与排版，FPGA只校验、缓存和发送。

沿用同一公共帧头、8位seq、长度和CRC；打印消息的count固定为01：

| 方向 / type | 载荷 | 含义 |
| --- | --- | --- |
| 主机→FPGA `82` | 非零job_id小端32位 + 1～512字节GBK文本 | 提交一次打印 |
| 主机→FPGA `83` | job_id小端32位 | 只查询、不打印 |
| FPGA→主机 `02` | job_id小端32位 + status一字节 + accepted_length小端16位 | 返回任务状态 |

status依次为`00 UNKNOWN`、`01 ACTIVE`、`02 SENT`、`03 BUSY`、`04 BAD_TEXT`、`05 ID_CONFLICT`。ACTIVE/SENT返回已接受的文本字节数，其余长度为0。状态与轨迹按完整帧仲裁，不将字节交错混发。32位job_id与书写seq独立；最近同ID同长度/载荷CRC指纹只回复状态、不重印，复位后不保留任务记录。

文本允许GBK双字节、可见ASCII及TAB/CR/LF；整帧格式、长度、文本结构和CRC正确后才提交。非法字节或残缺GBK整票拒绝，不透传ESC、切纸等任意命令，不自动识别UTF-8。FPGA只检查编码结构，不验证完整中文字库。无效半帧连续1秒无字节后丢弃，不中止已提交的任务。

主机小票按32西文列 / 16汉字排版，以CRLF分行并保留走纸空行；中文界面输出中文小票，英文界面输出英文小票。实机新行出现在旧行上方，游戏出口倒序发送已排版的行补偿，**行内文字和GBK字节不倒转**，FPGA不再二次反序。

主机只提交一次，之后查询状态；超时、断线或UNKNOWN不自动重印。SENT仅表示最后一个UART停止位已发完，不表示打印成功；清空/切模式不取消打印，S0会中止并可能留下半张小票。独立CH340观察时原始行序与预览不同属于上述补偿的预期行为。

<a id="verification"></a>

## 验证流程

1. 上电/S0：摄像头、DDR、自检页、FPS、OLED正常页和数码管；无回传不自动喵。
2. PEN：近远、快慢、边缘检测/轨迹及S2；确认后WAIT，回传后DONE/绿色字符/一声喵。
3. 不清空重复确认：不重发、不丢结果、不重复喵；清空后可重新书写。
4. 点/原地抖动/过短轨迹：不产生有效发送或假WAIT，清空后可重写。
5. HAND：单食指、握拳、比耶、张掌；检查阈值键与模式切换。
6. 按键/红外、数码管、OLED、HDMI视频/声音，连续书写与反复复位。
7. 主机断线恢复后清空重写，保留异常场景和对应日志。
8. 灯环：确认16颗均参与呼吸，WAIT/打印跑马能经过最后4颗并从15号回到0号；回传绿灯、清空和S0首帧清灯正常。
9. 打印：先短黑板文本，再选择一条原日期学习记录；确认一次只出一票、取消不输出、中文整字和行序正确，完成后原书写/回传/喵声仍正常。

上述流程用于部署后复现功能；长期可靠性需另外记录持续时间、连续次数和异常日志。

## 常见问题

| 现象 | 检查 |
| --- | --- |
| CT1135大量端口不存在 | 显式正确顶层，重新综合再P&R，不删除CST |
| ROM/IP文件缺失 | 完整复制src，保持工程内相对路径 |
| 正常画面但无声 | 新合法回传DONE、LPCM支持、音源/静音/音量 |
| 喵声太大 | 调整屏幕音量，当前无板载音量菜单 |
| OLED不亮 | SSD1306/0x3C、3.3V供电/BANK、SDA/SCL/共地/ACK |
| 一直WAIT | 主机端口、协议/seq/CRC、串口占用，恢复后清空重写 |
| HAND缺轮廓 | 检查绿手套在原画中的颜色、光照、同色干扰和书写范围；过度放宽门限会增加噪点 |
| 灯环只亮前12颗 | 是否仍下载旧12灯FS；重新综合当前16灯源码，核对DIN方向与供电 |
| 灯环乱色 / 闪烁 | 共地、短线、数据电平匹配；不提高GPIO BANK电压 |
| 小票乱码 / 不出字 | TTL版、A16→RX、9600/8N1、GBK、板载5V供电与装纸方向 |
| HDMI偶发无信号 | 对照线缆/接口、供电和显示器，并保留异常状态；当前尚未定位根因 |
| 下载失败或旧画面 | 核对器件、FS时间/指纹；改源码不等于已重新生成位流 |
